# 뉴스 계정 저장 · 2026-09-08

## 기존 구조와의 차이

뉴스 읽음·원문 열람 표시·보관·숨김·개인 분류·추적 검색만 계정별로 저장한다. 공개 기사 본문을 별도 정본으로 복제하지 않는다. 기존 취재 원장, 진행중 취재 메모, DART·출자·공개 취재 기능은 변경하지 않는다.

이메일 확인은 Supabase Auth에 맡긴다. 별도 비밀번호 저장·관리자 우회 확인·로그인 토큰 공개 엔드포인트는 만들지 않는다. 기존 /api/news의 reader 분기를 사용해 함수 수를 늘리지 않는다.

## 기록 보존과 공개 범위

시작할 때 브라우저에 남은 기록을 자동으로 표시하거나 계정으로 올리지 않는다. 뉴스 목록은 비로그인 상태에서도 볼 수 있다. 개인 동작은 로그인하거나 명시적으로 브라우저 저장을 선택한 뒤 실행한다.

로그인 후 본인 기록임을 확인하고 ‘브라우저 기록 가져오기’를 눌렀을 때만 옮긴다. ib-news-desk-v1과 ib-news-reader-v2는 지우지 않는다. 계정에 이미 있는 기록과 해제 이력은 기존 브라우저 기록으로 덮어쓰지 않는다. 원래 브라우저 기록은 공용 프로필에서 여전히 보일 수 있다.

계정 기록은 브라우저 메모리에만 올리며 localStorage에 복사하지 않는다. 로그아웃·계정 전환·저장 실패 시 개인 메모리를 비운다. 서버 연결 실패가 브라우저 저장으로 자동 전환되지 않는다. 개인 응답은 브라우저·공유 CDN 모두 no-store다.

## 접근 제한

확인된 사용자 JWT로 요청하고, 실제 데이터베이스 역할과 사용자 ID를 다시 검사한다. news_reader_records의 강제 행 수준 접근 제어는 본인 ID와 확인된 이메일을 모두 요구한다. 요청 본문에 user_id를 넣어 소유자를 바꾸지 못한다.

개인 기록은 버전이 맞을 때만 갱신한다. 다른 기기에서 먼저 바꾼 기록은 오류로 알리고 다시 읽도록 한다. 인증 요청은 서버에서 HMAC 처리한 이메일/IP별로 제한한다. 세션 쿠키는 Secure·HttpOnly·SameSite=Strict·__Host 접두사를 사용한다. 프로젝트 키는 소스에 넣지 않고 서버 환경에서만 읽는다.

## 확인한 것과 남은 것

실제 데이터베이스에서 임시 A/B 계정의 읽기 격리, 다른 소유자로의 삽입·수정 차단, 비로그인·미확인 이메일 차단, 버전 충돌 거부를 검사했다. 임시 계정과 데이터는 트랜잭션 롤백으로 남기지 않았다.

인증·저장 HTTP와 브라우저 상태를 모의 응답으로 검사하는 41개 테스트를 작성·실행했다. 실제 빌드 소스의 연결 순서·개인 기록의 로컬 저장 방지·변환 반복 실행을 검사하는 추가 테스트는 배포 빌드에서 실행한다. 메일 실제 수신부터 로그인·기기 간 저장까지 이어지는 운영 전체 검증은 아직 하지 않았다.

Supabase 기본 메일 서비스에는 수신자·발송량 제한이 있다. 일반 이용자 이메일로 발송하려면 프로젝트의 SMTP 설정이 필요할 수 있다. 발송 설정 변경 도구는 현재 연결에 없으므로 코드만으로 발송 가능 여부를 단정하지 않는다. 제한에 걸리면 로그인 화면에서 오류를 알린다. 확인 절차를 건너뛰지는 않는다.

기본 메일이 번호 대신 링크를 제공할 때는 링크를 누르지 말고 주소를 로그인 입력란에 붙여넣어 인증한다. 같은 Supabase 프로젝트의 검증 링크만 받아 토큰을 확인하며 임의 주소를 서버에서 열지 않는다. 더 간단한 번호 입력을 쓰려면 Magic Link 메일 템플릿에 Token을 포함해야 한다.

## 운영

SUPABASE_URL, SUPABASE_SECRET_KEY 또는 SUPABASE_SERVICE_ROLE_KEY를 서버에서 사용한다. 별도 SUPABASE_PUBLISHABLE_KEY 또는 SUPABASE_ANON_KEY가 있으면 일반 인증 요청의 프로젝트 식별 키로 우선 사용한다. 개인 데이터 요청에는 항상 확인된 사용자 JWT를 Authorization에 넣으며 서버 역할로 읽거나 쓰지 않는다. NEWS_READER_AUTH_ENABLED=0이면 계정 저장 기능을 끌 수 있다. 비밀번호·키·인증번호를 코드나 작업 로그에 적지 않는다.

DB 변경은 supabase/migrations/20260908053139~20260908054959 네 파일에 기록했다. 이 파일은 이미 적용한 변경의 기록이다. 기존 원장 스키마를 삭제하거나 다시 만드는 작업은 없다.
