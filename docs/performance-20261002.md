## 캐시와 최신성

- 브라우저 목록 캐시는 공개 뉴스·공시만 대상으로 한다. 계정별 읽음·보관·인증정보는 넣지 않는다. 세션 저장에 실패해도 메모리와 일반 요청으로 동작한다.
- 일반 조회와 수동 새로고침을 구분한다. 오래 걸린 이전 요청이 더 최근 결과를 덮어쓰지 않도록 요청 순서를 확인한다.
- 서버 소스 캐시는 인스턴스 내부 메모리다. 인스턴스 사이에서 공유되는 영구 저장소가 아니다. 데이터 수·용량·보관기간을 제한한다.
- 이전 정상 결과를 활용한 경우 이를 새로 수집한 것처럼 표시하지 않는다. 실제 소스 수집 시각과 현재 응답 시각을 구분한다.
- 취재파일 기본 응답은 확보한 내부·기초자료로 구성한다. 외부 뉴스·운용사 정보가 늦거나 실패해도 기본 파일을 표시한다.

## 검증 기준

- 같은 목록 요청의 중복 방지, 구독자별 취소, 강제 갱신과 일반 조회의 응답 순서 역전.
- 일부 수집 실패의 이전 정상 결과 유지, 보관기한 만료, 완전 실패와 성공 응답 구분.
- 느린 외부 뉴스·운용사 조회와 무관한 취재파일 기본 응답, 파일 전환 뒤 늦은 결과 차단.
- 검색·필터 조작 시 추천 재계산과 저장 생략, 새 자료·보강된 본문·원문 검토 도착 시 재계산.
- 공고 출처별 부분 표시, 갱신당 VCS 요청 한 번, 정책 탭 지연 조회.
- 실제 배포용 빌드 주입을 거친 전체 회귀 테스트·스키마 선언 검사·AI 규칙 평가.

검증 결과: `npm run vercel-build` 통과. 전체 테스트 826개, AI 운영 회귀 평가 17개 모두 통과했다. 스키마 선언 검사는 통과했으며 운영 DB 연결 검사는 하지 않았다. 수정 전 배포용 빌드의 전체 테스트는 784개였다.

## 적용 범위

이 변경은 재조회·중복 수집·화면 반복 계산을 줄이는 작업이다. 모든 수집을 정기 작업으로 이전하거나 영구 스냅샷을 미리 생성하는 구조까지 바꾸지는 않는다. 처음 수집하는 조건에서는 외부 사이트의 응답을 기다릴 수 있다. 외신 번역과 일정 전체 수집의 최초 대기, AI 공급자의 호출 제한은 별도 개선 대상이다.

테스트는 모의 네트워크로 동작과 요청 횟수를 검증한다. 운영 환경의 로딩 시간 개선 수치는 배포 이후 같은 조건에서 측정해야 한다.
