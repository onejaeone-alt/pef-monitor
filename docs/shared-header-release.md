# 공통 상단 · 로그인과 취재파일 검색 · 2026-09-08

## 변경

사이트 내부의 모든 topbar 페이지에 같은 상단을 적용한다. 오른쪽 첫 줄은 로그인, 둘째 줄은 취재파일 검색이다. 뉴스 목록 안에는 로그인 버튼을 만들지 않는다. 로그인한 상태에서는 같은 자리의 버튼을 ‘내 계정’으로 표시한다. 뉴스 183건 등 기존 상단 상태·건수 표시는 숨기되, 페이지 스크립트가 사용하는 status 요소는 남겨 오류를 방지한다.

왼쪽 제목 ‘IB 취재 레이더’와 기존 아이콘은 각각 같은 사이트의 `/`로 연결한다. 기존 탐색 메뉴, 본문, 원문, 취재파일 ID와 보관·취재 메모는 변경하지 않는다. 별도 도메인의 기사 엔진은 이번 변경 대상이 아니다.

기존 빌드 변환을 모두 실행한 뒤 integrate-site-header.js를 적용한다. 원본 HTML·이전 뉴스 코드·기존 계정 처리 모듈은 보존한다. 반복 빌드에도 링크·버튼·검색 제어기를 중복 생성하지 않는다. 검색은 기존 entity API와 dossier drawer를 쓰고, 오래된 응답을 숨기며 제목을 텍스트로 표시한다.

## 계정 처리 범위

뉴스 페이지는 기존 계정 제어기·로그인 창·가져오기 기능을 그대로 쓴다. 다른 페이지의 상단은 기존 status/send-code/verify-code/logout 경로만 쓴다. 뉴스 개인 기록을 다시 읽거나 저장하지 않는다. 확인 정보는 메모리에만 두며 localStorage와 취재 메모를 만지지 않는다. 인증 실패나 다른 탭의 계정 변경 시 이전 사용자 표시를 지운다. 세션·이메일 검증·개인 데이터베이스·RLS는 수정하지 않는다.

모든 페이지에 로그인 버튼을 두는 작업이며, 기존 로컬 취재 메모까지 계정별 저장으로 바꾸거나 보호하는 작업은 아니다.

## 검증

새 단위·통합 검사 22개를 로컬에서 실행했다. Chromium의 오프라인 DOM에서 8개 페이지 유형 × 5개 화면 폭(320~1440px)의 로그인 위치·검색 배치·건수 비표시·제목 링크와 별도의 계정·검색 동작을 점검했다. 인증·검색 응답과 뉴스의 기존 이벤트 연결은 테스트 응답을 사용했다. 이 검사는 실제 인증 메일 수신이나 운영 사이트 전체 로그인 검증을 대신하지 않는다.

미리보기와 운영 빌드에서 기존 전체 회귀검사를 유지한다. 실제 저장소 페이지의 공통 상단과 본문 보존도 검사한다. 운영 배포 결과는 도구 응답으로 별도 확인한다.
